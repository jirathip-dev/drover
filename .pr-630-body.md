Closes #630

## For humans
Each host now keeps everything herdsman makes in one workspace folder (default `~/.local/share/herdsman/work`): lane checkouts under it, one build cache per lane in its `.build` folder, started as a free copy of the newest one on the same drive.
A host can list several folders in order, for example a removable NVMe first and the internal disk second. New lanes use the first one that is plugged in and has room.
`herdsman hosts eject <host>` saves the lanes on the drive, restarts them on the next folder, and prints "safe to unplug" once nothing is left open there. A drive pulled without eject is noted once and its lanes restart on the internal folder.
`herdsman migrate` moves the old `~/.herdr/worktrees` checkouts into the new layout. Status and the board show each lane's unsaved work, and a repo can list setup files every new lane gets.

## What changed
- `[hosts.<n>] roots = [...]` (ordered; a single `root` still works). `roots::pick` picks the issue's last root while it can take lanes, else the first mounted, writable root with `min_free_gb`, else the last. Each `spawn` logs its `root`.
- The default worktree root moves from `~/.herdr/worktrees` to `~/.local/share/herdsman/work`. `[limits] build_root` is retired. Amendment A: each lane gets its own `CARGO_TARGET_DIR=<root>/.build/<agent>`, cloned copy-on-write at spawn (`spawn::clone_warm`: `cp -cR` on macOS, `cp -R --reflink=always` elsewhere) from the newest build folder of the same fleet's lanes on that root. It never crosses volumes, and the clone is logged `build-cloned` with `from`. Lane scratch stays at `<root>/.build/.scratch/<agent>`, and the scratch hook rule still reads `<root>/.build` from it. Sweep, trim (local and remote), `reclaim` and the worktree budget all read `<root>/.build`. Trim now also keeps a live lane's own build profiles (#634's guard), and ended lanes' builds go oldest first. The worktree budget leaves `.build` out, so caches never trigger `DISK_BUDGET`. `clean --orphans` skips dot folders.
- Amendment A: `.herdsman/worktree-include` (one path per line, `#` comments, no `..`) lists ignored files each new local lane worktree gets copied from the main checkout when missing (`spawn::copy_included`).
- Amendment A: unsaved work. `spawn::unsaved` counts uncommitted files and unpushed commits. `herdsman status` adds `· +<files> ⇡<commits>` for a local open lane. The lane sheet's facts line adds `root <path>` and `+N ⇡M`. `/api/v1/lanes` rows gain `root`, `dirty` and `unpushed` (`api.d.ts` regenerated).
- `herdsman hosts eject <host> [<root>]` logs `root-eject`, so new lanes skip that root at once. For each open issue's worktree there, it saves anything unpushed or dirty to `wip/<agent>-<stamp>` (kill's snapshot), removes the worktree, then respawns the issue's active lane with `--supersede`. That lane lands on the next root, from the branch that now holds the snapshot. The command prints `safe to unplug <root>` (exit 0) once no herdr agent's cwd is under the root; otherwise it exits 1 and names them.
- `check` → `roots::watch`: a root that had lanes and is now unmounted is logged `root-gone` once and printed as `! root <path> gone`. Its active lanes restart on the next root, and `root-moved` records what was lost. A root that comes back is logged `root-back`. Nothing moves back on its own.
- Visibility: `hosts.json`, `/api/v1` host data and the board's host card show each set root's path, state (`active` / `ejecting` / `gone`) and free GB, as new `root` rows. `herdsman status` shows `· root <path>` on each issue row, and the lane sheet's facts line shows `root <path>`. The waiting line adds `root gone, lost …` until the next push.
- `herdsman migrate` runs `git worktree move` on idle `~/.herdr/worktrees/<repo>/<lane>` worktrees. A live lane's worktree is left for a later run. Once nothing is left, `~/.cache/herdsman/target` is removed.

## Decisions
- **Build layout (fix round 1, per the reviewer and amendment A):** per-lane `<root>/.build/<agent>` replaces the shared `<root>/.build/<repo>`. Folders are named by agent rather than branch, because `issue-N` is the same in every repo and agents carry the fleet. "Warmest" means the build folder of a lane of the same fleet on that root that was changed most recently, which is normally the last lane that built. The main checkout's `target` is not used as a source, since it is often on another volume, where a clone becomes a full copy. Eject drops the cache, and the next root's lane clones from that root's warmest build. Disk totals are still `du` (apparent bytes shared by clones count once per lane), so `build_budget_gb` trims ended lanes' builds sooner. The amendment's "budgets use volume free space" refinement is not done here.
- **Pulled drive:** a worktree's commits live in the main checkout's `.git`, so only uncommitted work is really lost. The restart uses the local branch, which equals the pushed head unless there were unpushed commits; those are kept, not dropped. The `lost` text names the uncommitted work and counts the unpushed commits.
- **Root probing:** a host with a single root is never probed, so there is no extra ssh call at placement.
