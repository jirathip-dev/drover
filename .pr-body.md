## For humans
When nothing has changed on GitHub, the 15-second poll now costs no rate limit. It asks GitHub "anything new since last time?" three times; GitHub answers "not modified" for free, so the poll keeps its last full read. When something has changed, all of a fleet's PRs, checks and labels still arrive in one query.

## What changed
- `crates/core/src/gh.rs`: in the fast step, `snapshot` first sends three conditional REST probes (`gh api -i -H If-None-Match: <etag>`): open PRs sorted latest-updated first (heads, labels, titles), Actions runs (checks) and the integration branch (mergeability). It stores their ETags next to the snapshot. When all three answer 304, it reuses the last GraphQL result and stamps it fresh. It queries anyway 5 min (`PROBE_MAX`) after the last query, or while any PR's `mergeable` is `UNKNOWN`. A failed probe counts as changed. The batched GraphQL query itself (#246, `first:100`) is unchanged. Paths outside the fast step (`pr`, `wait`, `merge`, with the 60 s TTL) are unchanged.
- I checked against the live API: GraphQL responses carry no ETag. That is why the conditional requests are REST probes guarding the one GraphQL query. A 304 from `gh api -i` leaves `X-RateLimit-Used` unchanged.
- `docs/service.md`: describes the probes and marks deferred item (b) as built.
