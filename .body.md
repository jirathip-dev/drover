Closes #1215

## For humans
Finished lanes' build and scratch folders on remote machines are now cleared even when a tick runs long.
`drover reclaim` now frees them on enabled machines too, and never touches a live lane's folders.
Before refusing a spawn for low disk on a remote machine, drover clears those folders there first, and the refusal now names a command that frees space.
Recording a review verdict deletes that reviewer's scratch folder.
A lane that crashed or stopped running is now treated as finished, so its leftover folders are cleared too.

## What changed
- `timer.rs`: the tick lifts its budget for the `trim` step only, so the remote trim and scratch sweep run after drive even when drive overran. Clean, lesson, hotspots and compact are still skipped, and the message now says so.
- `check/sweep.rs` (moved out of `check.rs`, which is over its size baseline): `sweep` has a `Sweep` mode (`Tick` / `Preview` / `Apply`) and returns the bytes freed. `reclaim` sweeps each enabled remote host in Preview or Apply mode, which covers finished lanes only and skips the tick's disk-low branch. `drop_scratch` removes a lane's `.scratch/<agent>` folder here or on its host.
- `hosts.rs::disk_low`: on a remote host, it runs the sweep after the build trim and reads the disk again. The DISK_LOW text names `drover reclaim --apply`.
- `gate.rs::verdict`: frees the rev lane's scratch folder. This uses the same script that skips a folder whose cargo lock is held.
