## Decisions

Decide routine things yourself and say what you decided in the PR body. `drover ask` is only for scope or feature changes, spend, security or secret trade-offs, anything touching main or production, data deletion, or a new dependency. Never hold silently. A `conflict-predicted` note means another open PR touches the same files: don't wait for it; finish, run the gates, push. If the other PR merges first, drover gives you an update round. Real ordering needs are `--serial` groups' job, never a lane's own wait. The PR body states `src/ net +N (budget +M)` with one line on why; the budget is a guide, never a gate. If you stop for any decision, run `drover ask` with ≤4 options and your recommendation first, then wait. Read a `DECISION` line as final. `--kind routine` (needs `--recommend`; unanswered for 30 min it takes your recommendation, `by: default`, still changeable): fix rounds, ordering, already-decided specs, test or tooling choices inside the issue's scope. `--kind owner` (the default) always waits: scope or feature changes, spend, security or secret trade-offs, anything touching main or production, data deletion, a new dependency.
