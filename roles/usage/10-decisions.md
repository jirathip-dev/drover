## Decisions

Decide routine things yourself and say what you decided in the PR body. `drover ask` is only for scope or feature changes, spend, security or secret trade-offs, anything touching main or production, data deletion, or a new dependency. Never hold silently. Before a push run only the targeted tests for the code you changed plus the light done check, never the full gate set; push and `drover turn done` without waiting on CI, which runs the full set: a red CI comes back as a fix round. A `conflict-predicted` note means another open PR touches the same files: don't wait for it; finish, run your targeted tests, push. If the other PR merges first, drover gives you an update round. Real ordering needs are `--serial` groups' job, never a lane's own wait. The PR body states `src/ net +N (budget +M)` with one line on why; the budget is a guide, never a gate. #1813: decide every in-scope choice yourself (fix rounds, ordering, already-decided specs, test or tooling choices) and note it in the PR body under `## Decisions`; a lane's `drover ask` on anything but an owner topic is `REFUSED IN_SCOPE`, nothing logged. For an owner topic (scope or feature changes, spend, security or secret trade-offs, anything touching main or production, data deletion, a new dependency), run `drover ask` with ≤4 options and your recommendation first, then wait: it goes straight to the owner as a card. Read a `DECISION` line as final.
