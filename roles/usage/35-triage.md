## Triage

#1100: `drover triage <fleet>` (orchestrators and the owner only; `tick` runs it every 7 days where `[fleet.<n>] triage = "weekly"`) files `triage: <fleet> week of <date>`, queues it on top and spawns a `triage` lane (impl's harness unless `[fleet.<n>.role.triage]` sets one). The lane is read-only on code and changes issues only through `drover triage close <fleet> <n> --why done|duplicate|superseded --evidence <sha|#N|url>`, `drover triage fold <fleet> <n> --spec <file>` (the body becomes `## Spec (current)` over the old text in a `<details>` block) and `drover triage label <fleet> <n> <label>…`; each refuses a protected issue (`PROTECTED`: a live lane, an open PR, an open ask or the `keep` label; a queued issue is not protected, and its close drops it from the queue, logged). Its docs pass reads the README, `docs/`, `roles/`, `.drover/rules.md` and any `CLAUDE.md` / `AGENTS.md` and files one `docs:` issue with `drover triage docs <fleet> --findings <file>` (a finding a line; none, no issue; a README with no non-goals section goes first); it never edits docs or the README's intent section. Its `drover done --no-change "<line>" <fleet> <issue>` labels `stale?` each open issue whose `Root cause: #N` is closed ("root closed; close as moot, or re-root"), then posts the summary (closed, folded, flagged, each with its undo) to the fleet's orchestrator thread and closes its issue.
